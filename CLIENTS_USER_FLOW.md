# Раздел «Клиенты»: user flow

## 1. Назначение карты

Карта связывает:

- все экраны раздела;
- действия пользователя;
- действия Mary и AI-агентов;
- системные решения;
- успешные, пустые и ошибочные состояния;
- возвраты без потери контекста.

## 2. Легенда

| Тип | Обозначение |
| --- | --- |
| Экран | `C-XX` |
| Действие пользователя | `A-XX` |
| Решение системы | ромб |
| Действие Mary или агента | `M-XX` |
| Результат | `R-XX` |

## 3. Список экранов

| ID | Экран | Слой |
| --- | --- | --- |
| `C-01` | Список клиентов | Базовый |
| `C-02` | Загрузка списка | Базовый |
| `C-03` | Клиентов пока нет | Базовый |
| `C-04` | Поиск без результатов | Базовый |
| `C-05` | Ошибка загрузки | Базовый |
| `C-06` | Карточка клиента справа | Контекстный |
| `C-07` | Переписка с клиентом | Рабочее модальное окно |
| `C-08` | Окно Mary | Плавающий ассистент |
| `C-09` | Добавление клиента через Mary | Плавающий ассистент |
| `C-10` | Подтверждение опасного действия | Подтверждение |
| `C-11` | Недостаточно прав | Системное состояние |
| `C-12` | Канал отключён | Системное состояние |

## 4. Главный user flow

```mermaid
flowchart TB
    START(["Пользователь открывает раздел Клиенты"])
    LOAD["C-02 · Загрузка списка"]
    LOAD_OK{"Данные загружены?"}
    HAS_CLIENTS{"Есть клиенты?"}
    LIST["C-01 · Список клиентов"]
    EMPTY["C-03 · Клиентов пока нет"]
    ERROR["C-05 · Ошибка загрузки"]

    START --> LOAD
    LOAD --> LOAD_OK
    LOAD_OK -->|Нет| ERROR
    ERROR -->|"A-01 · Повторить"| LOAD
    LOAD_OK -->|Да| HAS_CLIENTS
    HAS_CLIENTS -->|Нет| EMPTY
    HAS_CLIENTS -->|Да| LIST

    LIST -->|"A-02 · Искать"| SEARCH{"Есть результаты?"}
    SEARCH -->|Да| LIST
    SEARCH -->|Нет| NORESULT["C-04 · Поиск без результатов"]
    NORESULT -->|"A-03 · Сбросить поиск"| LIST
    NORESULT -->|"A-04 · Добавить клиента"| ADD["C-09 · Добавление через Mary"]

    LIST -->|"A-05 · Применить фильтр"| FILTER{"Есть результаты?"}
    FILTER -->|Да| LIST
    FILTER -->|Нет| FILTER_EMPTY["C-04 · Фильтр без результатов"]
    FILTER_EMPTY -->|"A-06 · Сбросить фильтры"| LIST

    LIST -->|"A-07 · Нажать на строку"| DRAWER["C-06 · Карточка клиента справа"]
    DRAWER -->|"A-08 · Закрыть карточку"| LIST
    DRAWER -->|"A-09 · Выбрать другого клиента"| DRAWER

    LIST -->|"A-10 · Нажать иконку сообщения"| CHAT["C-07 · Переписка"]
    DRAWER -->|"A-11 · Открыть переписку"| CHAT
    CHAT -->|"A-12 · Закрыть"| DRAWER

    LIST -->|"A-13 · Спросить Mary"| MARY["C-08 · Окно Mary"]
    DRAWER -->|"A-13 · Спросить Mary"| MARY
    MARY -->|"A-14 · Закрыть"| RETURN{"Карточка была открыта?"}
    RETURN -->|Да| DRAWER
    RETURN -->|Нет| LIST

    LIST -->|"A-15 · Добавить клиента"| ADD
    EMPTY -->|"A-15 · Добавить клиента"| ADD
    ADD -->|"A-16 · Отмена"| LIST
    ADD -->|"A-17 · Подтвердить"| CREATED["R-01 · Клиент создан"]
    CREATED --> DRAWER
```

## 5. Flow карточки клиента

```mermaid
flowchart LR
    OPEN["C-06 · Карточка клиента"]

    OPEN --> IMPORTANT["Сейчас важно"]
    OPEN --> CONTACTS["Контакты"]
    OPEN --> TASKS["Ближайшие действия"]
    OPEN --> EVENTS["Последние события"]

    IMPORTANT -->|"Открыть переписку"| CHAT["C-07 · Переписка"]
    CONTACTS -->|"Изменить с Mary"| MARY["C-08 · Mary с контекстом клиента"]
    TASKS -->|"Открыть задачу"| TASK_DETAIL["Карточка задачи"]
    EVENTS -->|"Открыть событие"| EVENT_CONTEXT["Связанное обращение или заказ"]

    OPEN -->|"Заказы"| ORDERS["Список заказов в карточке"]
    OPEN -->|"Файлы"| FILES["Файлы и заметки в карточке"]
    OPEN -->|"Изменить с Mary"| MARY

    ORDERS -->|"Выбрать заказ"| ORDER_DETAIL["Детали заказа"]
    FILES -->|"Открыть файл"| FILE_PREVIEW["Просмотр файла"]

    CHAT -->|"Закрыть"| OPEN
    MARY -->|"Закрыть"| OPEN
    TASK_DETAIL -->|"Назад"| OPEN
    ORDER_DETAIL -->|"Назад"| OPEN
    FILE_PREVIEW -->|"Закрыть"| OPEN
```

### Правило вложенности

- `Заказы`, `Файлы`, задача и событие раскрываются внутри правой карточки.
- Они не создают отдельную страницу клиента.
- Переписка открывается поверх.
- Mary открывается отдельным плавающим окном.

## 6. Flow переписки и AI-агента

```mermaid
flowchart TB
    CHAT["C-07 · Переписка"]
    OWNER{"Кто ведёт обращение?"}

    CHAT --> OWNER
    OWNER -->|AI-агент| AGENT["M-01 · Агент анализирует сообщение"]
    OWNER -->|Сотрудник| HUMAN["Сотрудник пишет ответ"]

    AGENT --> CLASSIFY{"Можно ответить автоматически?"}
    CLASSIFY -->|Да| DRAFT["M-02 · Подготовить черновик"]
    CLASSIFY -->|Нет| HANDOFF["M-03 · Передать сотруднику"]

    DRAFT --> NEED_APPROVAL{"Нужно подтверждение?"}
    NEED_APPROVAL -->|Да| REVIEW["Черновик ждёт подтверждения"]
    NEED_APPROVAL -->|Нет| SEND["M-04 · Отправить ответ"]

    REVIEW -->|"A-18 · Подтвердить"| SEND
    REVIEW -->|"A-19 · Изменить с Mary"| MARY["C-08 · Mary редактирует черновик"]
    MARY --> REVIEW

    HANDOFF --> HUMAN
    HUMAN -->|"A-20 · Отправить"| SEND
    SEND --> RESULT["R-02 · Сообщение отправлено"]
    RESULT --> REPEAT{"Обращение повторяется?"}
    REPEAT -->|Да| SUGGEST["M-05 · Предложить автоматизацию"]
    REPEAT -->|Нет| CHAT
    SUGGEST -->|"A-21 · Обсудить"| MARY_AUTOMATION["C-08 · Mary собирает автоматизацию"]
    SUGGEST -->|"A-22 · Не сейчас"| CHAT
```

## 7. Flow добавления клиента

```mermaid
flowchart TB
    START["C-09 · Новый клиент через Mary"]
    METHOD{"Как передать данные?"}

    START --> METHOD
    METHOD -->|"Одной фразой"| TEXT["A-23 · Ввести имя, телефон, канал"]
    METHOD -->|"Ссылка"| LINK["A-24 · Вставить профиль"]
    METHOD -->|"Файл"| FILE["A-25 · Прикрепить список"]

    TEXT --> PARSE["M-06 · Mary распознаёт поля"]
    LINK --> PARSE
    FILE --> IMPORT["M-07 · Mary анализирует файл"]

    PARSE --> CHECK["Mary показывает резюме"]
    IMPORT --> DUPLICATES{"Найдены дубликаты?"}
    DUPLICATES -->|Да| MERGE["Mary предлагает объединить или пропустить"]
    DUPLICATES -->|Нет| CHECK
    MERGE --> CHECK

    CHECK --> VALID{"Данные корректны?"}
    VALID -->|Нет| EDIT["A-26 · Описать исправление"]
    EDIT --> PARSE
    VALID -->|Да| CONFIRM["A-27 · Добавить клиента"]
    CONFIRM --> CREATED["R-01 · Клиент создан"]
    CREATED --> DRAWER["C-06 · Карточка нового клиента"]
```

## 8. Flow действий через Mary

```mermaid
flowchart TB
    OPEN["C-08 · Mary открыта"]
    CONTEXT{"Есть выбранный клиент?"}

    OPEN --> CONTEXT
    CONTEXT -->|Нет| GENERAL["Mary работает со списком"]
    CONTEXT -->|Да| CLIENT["Mary получает клиента, обращение и заказ"]

    GENERAL --> SEARCH["Найти клиента"]
    GENERAL --> ADD["Добавить клиента"]
    GENERAL --> FILTER["Настроить фильтр"]

    CLIENT --> REPLY["Подготовить ответ"]
    CLIENT --> TASK["Создать или перенести задачу"]
    CLIENT --> ASSIGN["Назначить сотрудника или агента"]
    CLIENT --> EDIT["Изменить данные"]
    CLIENT --> HISTORY["Показать историю заказов"]
    CLIENT --> AUTOMATE["Предложить автоматизацию"]

    REPLY --> CONFIRM{"Действие требует подтверждения?"}
    TASK --> CONFIRM
    ASSIGN --> CONFIRM
    EDIT --> CONFIRM
    AUTOMATE --> CONFIRM

    CONFIRM -->|Да| DIALOG["C-10 · Подтверждение"]
    CONFIRM -->|Нет| EXECUTE["Mary выполняет действие"]
    DIALOG -->|"Подтвердить"| EXECUTE
    DIALOG -->|"Отмена"| OPEN
    EXECUTE --> SUCCESS["R-03 · Результат и краткое резюме"]
    SUCCESS --> OPEN
```

## 10. Таблица основных переходов

| Откуда | Действие | Куда | Что сохраняется |
| --- | --- | --- | --- |
| `C-01` | Клик по строке | `C-06` | Поиск, фильтры, сортировка, scroll |
| `C-06` | Закрыть | `C-01` | Позиция выбранной строки |
| `C-06` | Открыть переписку | `C-07` | Карточка клиента под модальным окном |
| `C-07` | Закрыть | `C-06` | Черновик, позиция диалога |
| `C-01` | Спросить Mary | `C-08` | Состояние списка |
| `C-06` | Спросить Mary | `C-08` | Клиент, обращение, заказ |
| `C-08` | Закрыть | `C-01` или `C-06` | Предыдущий контекст |
| `C-01` | Добавить клиента | `C-09` | Поиск и фильтры |
| `C-09` | Клиент создан | `C-06` | Новый клиент выбран |
| `C-04` | Сбросить поиск | `C-01` | Остальные фильтры |
| `C-05` | Повторить | `C-02` | Поиск и фильтры |

## 11. Переходы и анимации

| Переход | Анимация |
| --- | --- |
| `C-01 → C-06` | Панель справа, `240 ms`, drawer easing |
| `C-06 → C-01` | Панель вправо, `180 ms` |
| `C-06 → C-07` | Opacity + scale `0.98 → 1`, `180 ms` |
| `C-07 → C-06` | Opacity + scale `1 → 0.98`, `140 ms` |
| `C-01/C-06 → C-08` мышью | Появление окна, `180–220 ms` |
| `C-01/C-06 → C-08` через `⌘M` | Без анимации |
| Строка default → hover | Фон и иконка, `120 ms` |

## 12. Приоритет реализации

### P0

- `C-01`, `C-02`, `C-04`, `C-05`;
- `C-06`, `C-07`, `C-08`, `C-09`;
- поиск, фильтры, карточка, переписка, Mary;
- AI-агент и передача сотруднику;
- доступность с клавиатуры.

### P1

- `C-03`, `C-10`, `C-11`, `C-12`;
- импорт файла и обработка дубликатов;
- заказы, файлы и задачи внутри карточки;
- фоновая синхронизация.

### P2

- сохранённые фильтры;
- массовые действия;
- расширенная история изменений;
- персонализация колонок.

## 13. Критерии завершённости flow

- каждый пользовательский action имеет понятный результат;
- у каждого окна есть явный способ закрытия и возврата;
- список не теряет поиск, фильтры, сортировку и позицию;
- нет отдельной страницы клиента;
- карточка, переписка и Mary не конфликтуют по слоям;
- AI-агент и сотрудник различимы без зависимости от цвета;
- опасные действия требуют подтверждения;
- loading, empty, no-results, offline и forbidden имеют выход;
- desktop, tablet и mobile сохраняют одинаковую логику слоёв.
